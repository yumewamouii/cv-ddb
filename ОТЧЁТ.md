## 3. «Мои 3+3» и боксы (задание 2)

Слайд 3: три ожидания и три опасения, по одной строке на пункт. Боксы сделаны на scoped-CSS:

```css
.expect { background: #e8f2f7; border-left: 6px solid #1a5276; }
.fear   { background: #fdf1e3; border-left: 6px solid #d9822b; }
```

**Почему такие цвета.** Палитра взята из иллюстраций `pic/`: глубокий navy `#1a5276` — цвет заголовков колоды и основных блоков на картинках (`s01_cover`, `s12_shard`, `my_s17_key`), тёплый amber `#d9822b` — акцентный цвет стрелок, подсветки и «теплых» слоёв на тех же иллюстрациях. Фоны боксов — очень светлые производные этих цветов (`#e8f2f7` и `#fdf1e3`), чтобы текст оставался читаемым и боксы не спорили с картинками. Слева — толстая полоса 6 px: она кодирует смысл (navy = ожидание, amber = опасение) без дополнительных иконок.

Текст короткий: шесть боксов по одной строке плюс два подзаголовка. На слайде нет прокрутки, при 24 px и компактных отступах всё помещается в 16:9.

## 4. Фон и «плотный» слайд (задание 3)

### 4.1. Фон на своём слайде

Выбран **вариант B**: `![bg right:35% fit](pic/s12_shard.jfif)` на слайде-визитке. Это вертикальная иллюстрация 3:4, которая хорошо работает как правая колонка и не мешает тексту. ### 4.2. «Стратегии шардирования»: было → стало

**Было:** глобальный `section { font-size: 26px; }`, таблица 22 px, длинные формулировки в ячейках, примеры диапазонов `(1–1M, 1M–2M...)`, фраза «размер шардов неравный».

**Стало:** scoped-стиль по образцу «CAP-теоремы»:

```css
section { font-size: 21px; }
h2 { font-size: 30px; margin-bottom: 8px; }
table { font-size: 18px; }
```

Плюс сокращены формулировки:

| Было | Стало |
|---|---|
| диапазоны ключа (1–1M, 1M–2M...) | диапазоны ключа |
| range-сканы быстры | быстрые range-сканы |
| диапазоны бьют по всем шардам | диапазоны идут во все шарды |
| по списку значений (регион) | список значений (регион) |
| размер шардов неравный | шарды разного размера |

**Что помогло больше всего:** уменьшение шрифта таблицы до 18 px и удаление примеров из ячеек. Таблицу оставил: три стратегии сравниваются по четырём признакам, список из 12 строк читался бы хуже. Scoped-стиль применён только к этому слайду, остальная колода не поехала.

## 6. ИИ-фрагмент и рефлексия (задание 5)

На слайде «Виды прозрачности» заменена финальная фраза:

> **Компромисс**: чем выше прозрачность, тем больше работы система берёт на себя — и тем труднее локализовать сбой, когда что-то идёт не так.

В конце слайда стоит пометка:

```html
<!-- ИИ: черновик текста, отредактировано вручную -->
```

**Запрос к ИИ:** «Сформулируй одну строку для слайда о компромиссе прозрачности распределённой БД: чем выше прозрачность, тем сложнее диагностика. Без воды, 15–20 слов».

Заменил «магию» на «работу, которую система берёт на себя», а «разбираться» — на «локализовать сбой»: для курса про данные важна причинно-следственная связь, а не метафора. Проверил факт: прозрачность действительно скрывает распределение, но усложняет отладку; утверждение не обещает невозможного и не содержит чисел.


### Итерации

Промежуточные файлы не коммитились, сохранился только выбранный вариант; ниже — итерации формулировки промта.

1. **v1 — общая идея.** «Database sharding, three servers, data distribution». Результат был горизонтальным, с подписями и случайными стрелками; для `bg right:35%` не подходил, а текст на картинке генератор испортил.
2. **v2 — стиль и формат.** Добавлен блок `STYLE` из `промты_визуализации.md`, требование `no text, no letters, no numbers` и вертикальная композиция `-ar 3:4`. Картинка стала «из той же серии», но все стрелки шли во все шарды — не читалась идея изоляции запроса.
3. **v3 — композиция под смысл слайда.** Добавлен центральный hexagon (hash-функция), равномерные токены ключей, один amber-стрелка в выбранный шард и приглушённые teal-стрелки scatter-gather. Этот вариант и выбран: он показывает одновременно равномерность распределения и изоляцию типичного запроса по ключу.

**Что проверено:** нет текста и цифр, палитра navy/teal/amber совпадает с колодой, фон светлый, есть место под текст, вертикальный формат 3:4. Промт лежит комментарием перед изображением на слайде.

## 9. Бонус: CI (задание 8)

Файл `.github/workflows/slides.yml`. Важно: в тексте задания указан `marp-team/marp-action@v3`, но такого action в организации `marp-team` нет (проверено по GitHub). Поэтому workflow ставит официальный `@marp-team/marp-cli@4` через npm и собирает HTML командой:

```bash
marp --html --allow-local-files "01l_Введение_в_РБД.md" -o slides.html
```

Артефакт `slides` содержит `slides.html` и папку `pic/`, чтобы относительные пути к картинкам не ломались. После push в `main` зелёный прогон и артефакт видны на вкладке Actions.
